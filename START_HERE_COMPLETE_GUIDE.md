## ❓ Frequently Asked Questions

### Q: Is staging really necessary for our size?
**A (MO):** Yes. Staging pays for itself the first time it catches a bug before production. Cost is minimal ($25/month), setup is one-time (2-3 hours), and it prevents expensive production incidents. GitHub, Stripe, and every successful SaaS company uses staging.

### Q: Can we ship faster than weekly?
**A (MO):** Yes, but not recommended initially. Weekly releases balance speed with stability. Once the team is comfortable, we can move to daily/continuous deployment. Start with weekly, optimize later.

### Q: Why not just use feature flags without staging?
**A (MO):** Feature flags control who sees features, but staging gives you a place to test the full user experience before production. You want to catch bugs in staging (test data, test users) not in production (real data, real users). They complement each other.

### Q: What if 5% premium conversion is too optimistic?
**A (JO):** Gradual rollout lets us test. Start at 10% of users → measure conversion → adjust pricing/features → expand. If 3%, we add more premium value or lower price. If 8%, we found product-market fit. Flexibility is built in.

### Q: Do we have bandwidth for 12 weeks of feature work?
**A (Team):** Depends on priorities. If dashboard/journal/revenue are top priorities, we commit the team. If other projects are more urgent, we adjust timeline or scope. Need CEO to set priorities.

### Q: Can we start with just Dashboard or just Journal?
**A (JO):** Yes. Dashboard is easier (Weeks 1-3). Journal is more valuable (Weeks 3-10). Premium tier needs both to justify $9/month. Recommend shipping Dashboard first (quick win), then Journal (core value), then Premium (monetization).

### Q: What's the hardest part?
**A (MO):** Discipline. Weekly releases require process discipline (merge on Wednesday, release on Friday). Team must protect feature work (no major distractions for 12 weeks). Hardest part is organizational, not technical.

### Q: What if a major bug hits production?
**A (MO):** 
1. Disable feature via feature flag (instant, no redeployment)
2. Fix bug in feature branch
3. Test fix on staging
4. Deploy fix to production via hotfix process
5. Re-enable feature flag

Total time: 1-2 hours for critical bugs (vs. days without this process).
