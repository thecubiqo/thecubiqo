CUBIQO: Chronological Synthesis

Structured exclusively by the task order assigned by the Founder. Each phase juxtaposes the directives of Tela (Vision Spec), MO (Code/Business Audit), and AG (Advanced Engineering).

Task 1: Gap Analysis & Target Architecture

Initial Spec vs Reality
Tela's Spec

The Empathy Moat & 3D Avatar

The OS must visually reflect the AI's state. The interface relies on an expressive 3D Cuboid and the RGY (Red, Green, Yellow) Intent Routing mechanism mapping directly to specific voice personalities.

MO's Audit

40% Built. Core Works, Peripherals Missing

The core intelligence (Claude, ElevenLabs, Whisper) is functional natively at cubiqo.ai. The RGY system is 60% built but lacks advanced routing. Color/Voice mapping is 0% built. Side panels and keywords missing. Recommended patenting the RGY intent matching (60% success probability).

AG's Advice

Audio Sync & UI Integrity

The 3D UI must not be static. We must tie the Web Audio API's AnalyserNode directly to React Three Fiber so the cuboid pulses perfectly to TTS syllables. Also, requires an NLP pre-router to intercept self-harm intents and hard-shift to YELLOW (empathy) mode.

Task 2: Offline Intelligence & BYO Domains

Privacy Architecture
Tela's Spec

Zero-Retention Paranoia

Target audience values extreme privacy. Explicit instruction to ensure "Bring Your Own" models are fully supported so CubiQo cannot read user interactions.

MO's Audit

Correct The Marketing vs DB Reality

"Zero-Retention" claims are currently false liability. Memories are stored in Supabase. Must rewrite ToS and marketing to reflect GDPR "Consent-based retention." Must lock RED zones behind an 18+ Age Gate.

AG's Advice

True Offline App Generation

To actually achieve Tela's absolute privacy, we must move off the Vercel web-app. We pack Next.js into a Tauri/Electron wrapper and embed llama.cpp using local GPU processing. Zero cloud pings. Integrate ChromaDB for local file indexing.

Task 4: Social Army & Emergent Coding

Advanced Automations
Tela's Spec

The Hands-Free Worker

Containerizing The Puppeteer Bots

The Social Army will fail on Vercel Edge functions due to 10s timeout constraints. We must migrate the headless Chrome browser instances into continuous Docker containers on Railway/Render for indefinite operation.

Task 6: AI Orchestration & CAP Gateway

P1 · Month 1–3
Tela's Spec

Unified Policy Gateway (TFR-006)

All internal sub-domains — Job Hunt, Social Army, Emergent — must route through a unified CAP Orchestrator that inherits and propagates the current RGY zone. No module operates outside the zone intent system.

MO's Audit

UI ↔ Audio Analyser Syncing (AG-UI-1)

Connect the Web Audio API's AnalyserNode to the 3D Cuboid in React Three Fiber so it pulses to TTS amplitude in real-time. Currently the cuboid is static during voice output — this kills the premium feel.

AG's Advice

Implementation Path

Inject a PolicyGateway singleton in /lib/policy/. Each module submits request + current RGY zone; gateway validates intent before routing. For audio sync: capture the TTS stream into an AudioContext, pipe through AnalyserNode, pass amplitude array as a useFrame uniform to the Three.js shader.

✅ AG-ROUTING-1 SHIPPED: Self-harm intercept implemented in /api/chat/route.ts — detects crisis signals and hard-routes to YELLOW empathy mode with 988 + crisis resources.

Task 7: Voice Personas & Unified Input

P1 · Month 1–3
Tela's Spec

Distinct Voice Personalities (TFR-007)

Each RGY zone maps to a distinct ElevenLabs voice ID: Teal (calm, professional), Red (intense, direct), Yellow (warm, empathetic). Micro-interactions: a wake chime on session start, subtle ticks during STT processing, haptics on mobile.

MO's Audit

Vocspad Unified Input Surface (TFR-008)

Merge voice and text into a single input surface. Live Whisper STT transcription must append text to the input field in real-time as the user speaks — not dump it all at once when they stop. This is currently two separate UX paths; users expect one.

AG's Advice

Implementation Path

Use the Web Speech API's SpeechRecognition.onresult event to stream interim results into a shared inputText state. On final result, auto-submit. For voice personas: add a voiceId map in /config/voices.ts keyed to RGY zone, pass to the TTS route. Micro-interactions via the Web Vibration API + custom CSS animations.

Task 8: Retention, Onboarding & 3D Animations

P1 · Month 1–3
Tela's Spec

5-Branch Onboarding Flow (TFR-014)

Onboarding must be a curated, intentional sequence that branches based on the user's declared intent: Solopreneur, Developer, Hustler, Companion, Privacy-First. Each branch customises the initial RGY zone, voice persona, and suggested first interaction.

MO's Audit

Missing 3D Animations & Analytics Funnel (TFR-009 + TFR-012)

Three 3D animations are missing: Wink (playfulness), Trust Earned (milestone), Handoff (sub-agent delegation). Analytics funnel must expand to 15 events via PostHog — critical for measuring Activation rate target of >20%.

AG's Advice

Implementation Path

Onboarding: create 5 OnboardingPath config objects, store selection in DB (onboarding_data.intent). Animations: define Three.js morph targets or GSAP keyframe sequences for Wink/Trust/Handoff; trigger from chat events. PostHog: add posthog.capture() at 15 funnel stages from page_view through voice_first_use.

✅ SHIPPED (REQ-02 + REQ-03): onboarding_data + onboarding_completed columns live in profiles. Auth callback routes new users to /onboarding automatically.

Task 9: Spending Caps, Peer Connections & CQ Network

P1 · Month 1–3
Tela's Spec

CQ↔CQ Peer Matching (TFR-010)

Expose CQ numbering system in profiles. Enable direct WebRTC WebSocket chat for RGY-matched peers. Two users with complementary intent profiles (e.g. one Hustler + one Developer) should be able to see each other and connect.

MO's Audit

Spending Caps Must Persist (TFR-011)

In-memory spending limits reset on every Vercel deploy/restart — meaning the $200/mo hard cap can be bypassed simply by triggering a redeploy. Limits must be persisted in the usage_tracking Supabase table and enforced at query-time.

AG's Advice

Implementation Path

Spending: checkSpendingCap() already queries Supabase — verify it sums the current billing cycle correctly. Peer matching: add cq_number to profiles, implement a /api/rgy/match endpoint that queries compatible intents within radius, and create a WebSocket channel via Supabase Realtime.

✅ SHIPPED (REQ-08): checkSpendingCap() and recordSpending() now use Supabase usage_tracking table. 429 responses enforced in /api/chat and /api/tts.
