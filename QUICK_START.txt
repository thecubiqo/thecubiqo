QUESTION 2: How do I test locally?
================================================================================

STEP 1: Open Terminal/Command Prompt

STEP 2: Navigate to your project
  $ cd /path/to/thecubiqo

STEP 3: Install dependencies (first time only)
  $ npm install

STEP 4: Run development server
  $ npm run dev

STEP 5: Open browser
  → Go to: http://localhost:3000

DONE! ✅ Your site is running on your computer!

Alternative: Build for Production
  $ npm run build      # Compile everything
  $ npm start          # Run production server


QUESTION 3: How do I push to GitHub?
================================================================================

STEP 1: Check what changed
  $ git status

STEP 2: Add all changes
  $ git add .

STEP 3: Commit with message
  $ git commit -m "Fixed auth and build issues"

STEP 4: Push to GitHub
  $ git push origin the-merger

That's it! ✅ Your code is now on GitHub!


QUESTION 4: How does Vercel deployment work?
================================================================================

AUTOMATIC PROCESS (No commands needed!):

  1. You push code to GitHub
         ↓
  2. Vercel detects the push
         ↓
  3. Vercel runs: npm install && npm run build
         ↓
  4. Vercel deploys to internet
         ↓
  5. You get a URL!

DEPLOYMENT TYPES:

  Production (main branch):
    → URL: www.cubiqo.ai
    → This is your live site

  Preview (other branches):
    → URL: the-merger-cubiqo.vercel.app
    → Safe testing environment

WHERE TO SEE DEPLOYMENTS:
  → Vercel Dashboard: https://vercel.com
  → Or check Pull Request on GitHub (Vercel bot comments with link)

                        🔧 SUPABASE SETUP (Later)
================================================================================

WHAT IS SUPABASE?
  → Your database (stores user data, chats, etc.)
  → Your auth system (handles login)

SETUP STEPS (Do after reviewing the-merger):

  1. Go to: https://supabase.com/dashboard
  2. Log in to your account
  3. Click your project
  4. Go to: Settings → API
  5. Copy these 3 values:
     - Project URL
     - Anon/Public key
     - Service Role key

  6. Add to Vercel:
     - Go to Vercel dashboard
     - Click your project
     - Settings → Environment Variables
     - Add:
       NEXT_PUBLIC_SUPABASE_URL=your-url
       NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
       SUPABASE_SERVICE_ROLE_KEY=your-service-key

  7. Redeploy on Vercel
  8. Test authentication!


================================================================================
                        🆘 COMMON ERRORS & SOLUTIONS
================================================================================

ERROR: "Permission denied" when pushing
SOLUTION:
  $ git config --global user.name "Your Name"
  $ git config --global user.email "your@email.com"
  OR: Use GitHub Desktop (easier for beginners!)

ERROR: "Port 3000 already in use"
SOLUTION (Mac/Linux):
  $ lsof -ti:3000 | xargs kill -9

SOLUTION (Windows):
  $ netstat -ano | findstr :3000
  $ taskkill /PID [the number] /F

ERROR: "Module not found"
SOLUTION:
  $ npm install

ERROR: Vercel build fails
SOLUTION:
  → Check build logs in Vercel dashboard
  → Look for red error messages
  → Usually: missing env variables or npm install needed
